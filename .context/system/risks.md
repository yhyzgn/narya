# 风险登记

## 风险一：上下文漂移

- 触发条件：代码、配置或工作流变化后，没有同步更新对应上下文文件。
- 缓解措施：根据变化的事实或生命周期状态更新 `system/`、计划或任务。
- 回滚方式：只回滚上下文变更，不改变源码行为。

## 风险二：遗留迁移丢失

- 触发条件：未做语义分类就机械移动 `prompt.md`、`.memory/` 或 `.prompt/`。
- 缓解措施：先生成迁移清单；所有长期事实和可执行任务完成核对前保留来源文件。
- 回滚方式：从未改动的来源文件恢复，只删除生成的上下文文件。

## 风险三：假连接状态（高）

- 证据和影响范围：`crates/narya-app/src/state.rs` 与 `crates/narya-daemon/src/main.rs` 通过多个 IPC 请求驱动状态；当前无 framing、健康探针和副作用回滚。
- 触发条件：内核启动成功但系统代理/TUN 设置失败，或读取边界拆分多个 JSON 消息。
- 失败模式：UI 显示已连接但流量未按预期转发，或断开后残留系统代理。
- 缓解措施和必需验证：引入有长度前缀的 IPC、事务式 apply/rollback、内核健康检查和离线故障测试。
- 回滚或隔离动作：在新控制面稳定前保留旧 IPC 方法但默认 fail-closed，不宣称连接成功。
- 负责人和状态：Codex；UI 只在 `StartKernel`、`SetRoutingMode` 和健康状态均成功后显示运行，daemon 离线不再模拟流量；仍需真实权限/路由/DNS 流量探针。

## 风险七：内核工件发布者信任根（高）

- SHA-256 保证内容完整性，Ed25519 字段保证请求中签名匹配，但当前应用尚未内置官方公钥发布清单。
- 在发布清单完成前，HTTPS 工件安装只能由明确输入的签名/公钥请求触发，不能提供自动下载或自动升级。

## 风险四：规则与 TUN 语义漂移（高）

- 证据和影响范围：`crates/narya-rules/src/lib.rs` 尚为占位，`config_gen.rs` 只支持 Shadowsocks 与 DNS 规则。
- 触发条件：系统代理与 TUN 使用不同的规则编译路径，或内核能力差异未被显式建模。
- 失败模式：同一域名在两种模式下走不同出口、DNS 泄漏或规则静默失效。
- 缓解措施和必需验证：建立统一规则 AST/优先级模型，分别生成各内核配置并用 golden tests 对照。
- 回滚或隔离动作：未知匹配条件和不支持的内核能力必须报错，不回退到 direct。
- 负责人和状态：Codex；规则从 UI 状态随 `StartKernel` 进入 daemon 并统一编译，仍需各内核能力矩阵、分流组编辑器和真实 TUN 流量探针。

## 风险五：DNS 污染与泄漏（高）

- 证据和影响范围：Karing 对照提交 `ae12111876a4456cc58c7410950428345f908abb` 在 `setting_manager.dart` / `server_manager.dart` 中把 resolver、direct、proxy、outbound DNS 与 TUN `hijack_dns` 分开建模；当前 Narya 没有这些边界。
- 触发条件：system proxy、TUN、规则匹配和 DNS 使用不同的出口决策，或断开时 fake-IP/路由未恢复。
- 失败模式：DNS 泄漏、污染、断开后缓存/路由残留，用户看到“已连接”但解析路径未生效。
- 缓解措施和必需验证：把 DNS 决策作为规则动作的一部分，增加污染/泄漏探针、断开恢复测试和每内核 golden config；任何探针失败都阻止 connected 状态。
- 回滚或隔离动作：默认关闭未验证的 fake-IP/TUN hijack；回滚时先恢复 DNS、代理和路由，再停止内核。
- 负责人和状态：Codex；DNS 配置生成已显式分离且未匹配 block，仍需真实解析污染/泄漏探针和断开后系统恢复验证。

## 风险六：平台代理能力不一致（高）

- 证据和影响范围：`crates/narya-daemon/src/proxy.rs` 当前只对 Linux GNOME 实现完整快照/apply/restore；macOS 与 TUN 明确返回 unsupported，Windows 尚未接入。
- 触发条件：在未实现平台上调用 `SetRoutingMode`，或发行版没有 `gsettings`/权限不足。
- 失败模式：连接动作被拒绝；不会假报成功，但用户需要明确的能力提示。
- 缓解措施和必需验证：每个平台 backend 单独实现快照、apply、restore 和 fake tests；真实流量探针通过后才能开放默认模式。
- 回滚或隔离动作：保持 fail-closed，不修改系统代理；Linux apply 失败自动恢复捕获快照。
- 负责人和状态：Codex；进行中。

## 风险三：外部依赖副作用

- 触发条件：校验或测试连接共享数据库、队列、缓存或远程接口。
- 缓解措施：优先离线检查，只运行明确授权的隔离验证。
- 回滚方式：产生副作用前停止，并在当前任务中记录阻塞证据。
