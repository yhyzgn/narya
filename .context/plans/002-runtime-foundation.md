# 计划 002：可靠运行时基础与统一分流

- 状态：进行中
- 负责人：Codex
- 当前任务：`.context/tasks/005-karing-rule-config.md`

## 目标

建立可验证的多内核、统一规则和代理模式控制面，避免假连接、假断开、静默 fallback 与配置污染。

## 非目标

- 本计划不固化旧 PNG 视觉设计，不恢复旧阶段 UI 规格。
- 不在没有平台证据和签名校验前实现自动下载生产内核。
- 不把单一内核私有配置格式冒充统一规则语义。

## 约束

- UI 继续使用 GPUI + Liora，但页面只能消费稳定的运行时契约。
- 系统代理与 TUN 必须共享同一规则 AST 和出口选择语义。
- 不支持的协议、规则条件、平台能力必须显式报错；禁止 direct 兜底。
- 不连接共享基础设施做测试。

## 依赖关系

```text
领域模型与 framing → 规则 AST/编译器 → 内核注册/安装 → 代理/TUN 事务 → UI 绑定
```

## 阶段

1. 完成规则模型、优先级和可测试编译契约。
2. 完成内核注册表、版本与安装/升级状态机。
3. 完成 framing IPC、健康探针及代理/TUN apply/rollback。
4. 以 Karing 公开实现和内核官方文档校准配置生成与端到端验证。

## 检查点

- 每阶段先有纯离线单元/契约测试，再接入平台副作用。
- 任何状态变更都记录可回滚点和失败状态。

## 计划级风险

- 各内核规则能力不等价，需要能力矩阵而非字符串替换。
- TUN 需要操作系统权限、路由和 DNS 处理，无法仅凭 UI 验证。
- Karing 的实现可能随上游更新，必须锁定引用版本和 golden fixtures。

## 完成标准

- 规则在 system proxy 与 TUN 配置中保持相同匹配顺序和出口语义。
- 内核安装、升级、切换和健康状态可观察、可回滚。
- IPC 对拆包/粘包安全，连接状态只由健康探针确认。
- 关键路径有离线测试与明确未覆盖风险。
