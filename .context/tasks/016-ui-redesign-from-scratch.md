# 任务 016：从零重做人机交互界面

- 状态：进行中
- 计划：`.context/plans/002-runtime-foundation.md`
- 规模：大
- 依赖：`.context/tasks/015-ui-layout-interaction-audit.md`
- 生产行为变更：是

## 任务目标

不依赖已删除的 `ui/` 图片或旧页面规格，从用户任务和运行时状态重新设计 Narya 的导航、页面层级、布局、控件和交互反馈。

## 范围

- 统一应用壳层、导航、标题栏、内容区和浮层的交互模型。
- 配置页仅展示配置订阅列表；导入入口统一在右上角，通过 Liora Drawer 选择远程、本地、剪贴板导入。
- 仪表盘、节点、订阅、规则、日志、工具和设置页面逐页重做，保证收缩、滚动、空状态、错误状态和操作反馈清晰。
- 所有交互控件使用 Liora；缺失能力先增强 Liora。
- 所有控件 ID 稳定且在重复列表中按业务实体隔离。

## 非目标

- 不恢复已删除的 `ui/` 图片、旧 HTML 草案或旧坐标规范。
- 不改变 daemon、代理、TUN、内核、规则和持久化语义。
- 不新增 WebView、HTML/CSS runtime 或第三方 UI 框架。

## 验收标准

- 每个页面有清晰的主任务、次任务和空/错/加载状态。
- 页面在最小窗口和正常窗口下均不越界、不遮挡，内容可滚动。
- 导航、Drawer、Input、Select、Switch、Button 等交互可点击、可键盘操作且反馈明确。
- 配置页主体只显示配置订阅列表，导入方式集中在一个右上角入口。
- 所有变更按阶段完成编译、测试、启动探针后提交并推送。

- 已完成配置页收敛为订阅列表和统一导入入口的第一版。
